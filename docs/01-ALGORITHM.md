# 01. 입지 적합도 알고리즘 설계서

문서 버전: v1.0 / 작성일: 2026-09-09
대상 독자: 구현자 (본 문서만으로 `lib/scoring/` 전체를 구현할 수 있어야 함)

---

## 1. 설계 원칙

1. **모든 축은 0~100 정규화** — 축 간 단위 이질성 제거, 레이더 차트 직접 표현
2. **정규화는 구간 선형보간(piecewise linear)** — 임계값이 사용자 직관과 일치하고 설명 가능
3. **결측은 0점이 아니라 제외** — 데이터 없는 축은 가중치에서 빼고 나머지를 재정규화
4. **감점은 별도 축** — RISK는 가산 축이 아니라 총점에서 차감 (최대 -15)
5. **모든 점수는 근거 문자열을 동반** — `{score, raw, reason, sources[], asOf}` 구조 강제
6. **블랙박스 금지** — 사용자는 상세 화면에서 각 축의 원자료와 계산 근거를 볼 수 있어야 함

## 3. 총점 산출식

```
가용축 집합 A = { i | score_i 가 결측이 아님 }

              Σ(i∈A) w_i · s_i
BaseScore = ─────────────────────      (0 ~ 100)
                 Σ(i∈A) w_i

TotalScore = clamp( BaseScore − RiskPenalty , 0 , 100 )

RiskPenalty = min( 15 , Σ 개별리스크감점 )
```

**신뢰도(confidence)** 를 함께 표기한다:

```
confidence = Σ(i∈A) w_i / 100        →  0.0 ~ 1.0
표기: ≥0.9 "높음" / 0.7~0.9 "보통" / <0.7 "낮음 — 데이터 부족"
```

**등급 매핑**

| 총점 | 등급 | 라벨 |
|---|---|---|
| 85~100 | S | 최적 입지 |
| 75~84 | A | 우수 |
| 65~74 | B | 양호 |
| 55~64 | C | 보통 |
| 40~54 | D | 조건 미흡 |
| 0~39 | E | 부적합 |

## 4. 공통 유틸

### 4.1 구간 선형보간

```ts
type Breakpoint = [input: number, score: number]

// 예: piecewise(42, [[30,100],[60,55],[90,10],[120,0]]) → 82.0
function piecewise(x: number, points: Breakpoint[]): number {
  if (x <= points[0][0]) return points[0][1]
  const last = points[points.length - 1]
  if (x >= last[0]) return last[1]
  for (let i = 0; i < points.length - 1; i++) {
    const [x1, y1] = points[i], [x2, y2] = points[i + 1]
    if (x >= x1 && x <= x2) return y1 + ((x - x1) / (x2 - x1)) * (y2 - y1)
  }
  return 0
}
```

### 4.2 도보 시간 환산

```
보행속도 = 67 m/min  (성인 평균 4.0 km/h, 한국 보행자 신호주기 설계 기준 준용)
도보시간(분) = 직선거리(m) × 우회계수 1.25 / 67
```
우회계수 1.25 = 도심 격자 도로망의 실거리/직선거리 평균 근사치.
카카오 로컬 API가 반환하는 `distance`(직선거리)를 실보행거리로 보정하기 위함.

### 4.3 면적 환산

```
1평 = 3.305785 ㎡     (1평 = 400/121 ㎡)
평 → ㎡ : x × 3.305785
㎡ → 평 : x ÷ 3.305785
```
입력은 전용면적 기준. 공급면적 입력 시 전용률 74% 가정 경고 표시.

## 5. 축별 상세 알고리즘

### 5.1 COMMUTE — 사무실 통근 (w=20)

**요구사항**: 30분 이내 최고, 1시간 30분 이상 최저.

**입력**: 단지 좌표, 사무실 좌표, 통근 수단(대중교통/자차)
**소스**: ODsay `searchPubTransPathT` (출발·도착 좌표 → 총 소요시간, 환승횟수)

**도어투도어 시간**:
```
T = 단지→최근접정류장 도보 + ODsay totalTime + 하차정류장→사무실 도보
```

**정규화**:
```
piecewise(T, [[0,100],[30,100],[45,80],[60,55],[75,32],[90,10],[120,0]])
```

| T(분) | 30 | 40 | 50 | 60 | 70 | 80 | 90 | 100+ |
|---|---|---|---|---|---|---|---|---|
| 점수 | 100 | 86.7 | 71.7 | 55 | 40.3 | 23.3 | 10 | ≤6.7 |

**보정**:
- 환승 0회 → ×1.05 (상한 100)
- 환승 3회 이상 → ×0.92
- 자차 통근 선택 시 ODsay 대신 카카오내비 예상시간, 출근시간대(08:00) 기준

**근거 문자열 예**: `대중교통 47분 (환승 1회, 도보 12분 포함) — 기준 30분 대비 +17분`

---

### 5.2 VALUE — 가격 대비 주변 시세 (w=15)

**입력**: 사용자 입력 매입 희망 금액, 전용면적
**소스**: 국토부 실거래가 상세 API — 해당 법정동 + 인접 법정동, 최근 6개월

**비교군 정의 (엄격도 순으로 폴백)**:
1. 동일 단지, 전용면적 ±3㎡, 최근 6개월 → 최소 3건이면 채택
2. 반경 1km 내 단지, 전용면적 ±5㎡, 최근 6개월 → 최소 5건
3. 동일 법정동 전체, 전용면적 ±10㎡, 최근 12개월 → 최소 5건
4. 미달 시 `결측` 처리

```
P_user   = 입력금액 / 전용면적(평)          (만원/평)
P_market = median(비교군 평단가)             (이상치 제거: IQR 1.5배 밖 제외)
ratio    = P_user / P_market
```

**정규화** (낮을수록 좋음):
```
piecewise(ratio, [[0.75,100],[0.85,95],[0.95,80],[1.00,70],[1.05,55],[1.15,30],[1.30,5],[1.50,0]])
```

**근거 예**: `평당 4,120만원 — 반경 1km 84㎡ 중앙값 4,480만원 대비 8% 저평가 (거래 17건, 2026-03~08)`

### 5.3 SUBWAY — 지하철 접근성 (w=13)

**서브스코어 3종 가중 합성**:
```
SUBWAY = 0.50 × 근접성 + 0.30 × 사무실직결성 + 0.20 × 자주가는장소직결성
```

**(a) 근접성** — 최근접 지하철역 도보시간 W
```
piecewise(W, [[3,100],[5,95],[8,80],[10,70],[15,40],[20,15],[25,0]])
```
가산: 반경 800m 내 역이 2개 이상(더블역세권) → +5, 환승역이면 +5 (상한 100)

**(b) 사무실 직결성** — 최근접역에서 사무실 최근접역까지
| 조건 | 점수 |
|---|---|
| 환승 0회 (직통) | 100 |
| 환승 1회 | 70 |
| 환승 2회 | 45 |
| 환승 3회 이상 | 20 |

**(c) 자주 가는 장소 직결성** — 등록 장소별 위 표 적용 후 **중요도 가중 평균**

**근거 예**: `2호선 강남구청역 도보 7분 (더블역세권) / 사무실역까지 직통 6정거장`

---

### 5.4 BUS — 버스 접근성 (w=8)

```
BUS = 0.40 × 정류장근접성 + 0.35 × 사무실버스직결성 + 0.25 × 자주가는장소버스직결성
```

**(a) 정류장 근접성** — 최근접 정류장 도보시간 W
```
piecewise(W, [[2,100],[4,90],[6,75],[10,50],[15,20],[20,0]])
```
가산: 반경 500m 내 정류장 3개 이상 → +5, 광역/M버스 정차 → +5

**(b/c) 직결성** — ODsay 버스전용 경로 탐색 결과
| 조건 | 점수 |
|---|---|
| 한 번에 감 (환승 0) | 100 |
| 1회 환승 | 60 |
| 2회 이상 환승 | 25 |
| 버스 경로 없음 | 0 |

**근거 예**: `정류장 도보 3분 / 사무실까지 간선 471번 직통 (환승 없음, 38분)`

### 5.5 SCHOOL — 학군 접근성 (w=12)

**가구 구성에 따라 하위 가중치 동적 조정**:

| 가구 유형 | 초 | 중 | 고 |
|---|---|---|---|
| 기본 | 0.45 | 0.30 | 0.25 |
| 미취학 자녀 | 0.60 | 0.25 | 0.15 |
| 초등 자녀 | 0.70 | 0.20 | 0.10 |
| 중고등 자녀 | 0.15 | 0.40 | 0.45 |
| 자녀 없음 | 0.33 | 0.33 | 0.34 |

**초등학교** (도보 안전 최우선, 임계 엄격):
```
piecewise(W, [[3,100],[5,95],[8,75],[10,60],[15,30],[20,5],[25,0]])
```
감점: 통학로에 왕복 6차선 이상 간선도로 횡단 → −10 (카카오 도로 데이터 기반, MVP는 사용자 체크)

**중학교**:
```
piecewise(W, [[5,100],[10,85],[15,65],[20,40],[30,10],[40,0]])
```

**고등학교** (대중교통 통학 허용, 가장 완만):
```
piecewise(W, [[5,100],[10,90],[15,75],[20,55],[30,25],[45,0]])
```

**근거 예**: `삼성초 도보 6분 / 언주중 도보 11분 / 경기고 도보 18분`

### 5.6 RETAIL — 대형마트 접근성 (w=5)

**소스**: 카카오 로컬 카테고리 검색 `MT1`(대형마트), 반경 3km

```
RETAIL = max( 도보점수 , 차량점수 × 0.85 )
```
- 도보점수: `piecewise(W, [[5,100],[10,85],[15,65],[20,40],[30,10],[40,0]])`
- 차량점수: `piecewise(D_km, [[1,100],[2,90],[3,75],[5,55],[8,25],[12,0]])`

가산: 반경 1.5km 내 대형마트 2개 이상 → +5 / 창고형 매장(코스트코·트레이더스) 포함 → +5

**근거 예**: `이마트 OO점 도보 12분 (900m) — 차량 4분`

### 5.7 AMENITY — 커뮤니티 센터·관리비 (w=5)

```
AMENITY = 0.55 × 커뮤니티시설점수 + 0.45 × 관리비점수
```

**(a) 커뮤니티 시설** — 보유 항목 수 기반 (사용자 체크 + 공동주택 정보)

| 항목 | 배점 |
|---|---|
| 실내 수영장 | 20 |
| 피트니스센터 | 15 |
| 실내 골프연습장 | 10 |
| 독서실/스터디룸 | 10 |
| 어린이집/유치원(단지 내) | 12 |
| 카페/라운지 | 8 |
| 게스트하우스 | 7 |
| 실내 놀이터·키즈룸 | 8 |
| 사우나/찜질 | 5 |
| 다목적체육관 | 5 |
| **합계 상한** | **100** |

세대수 보정: 500세대 미만 → ×0.9 (시설 운영 지속성 리스크), 1,500세대 이상 → ×1.05

**(b) 관리비** — ㎡당 월 관리비 vs 동일 시·군·구 평균 (K-apt 공동주택관리정보)
```
r = 단지관리비단가 / 지역평균단가
piecewise(r, [[0.70,100],[0.85,88],[1.00,70],[1.15,45],[1.35,20],[1.60,0]])
```
주: 커뮤니티가 좋으면 관리비가 오르는 **트레이드오프**가 정상이므로 두 항목을 분리 표기하고
상세 화면에서 "커뮤니티 상위 / 관리비 상위" 형태로 병기한다.

### 5.8 AGE — 단지 노후도 (w=7)

**U자형 곡선을 채택한다.** 신축이 최고점이나, 30년 이상은 재건축 기대가 반영되어 반등한다.

```
y = 준공 후 경과 연수
piecewise(y, [[0,100],[5,97],[10,88],[15,74],[20,60],[25,48],[30,42],[33,52],[36,62],[40,68],[50,60]])
```

| 연차 | 0 | 5 | 10 | 15 | 20 | 25 | 30 | 35 | 40 | 50 |
|---|---|---|---|---|---|---|---|---|---|---|
| 점수 | 100 | 97 | 88 | 74 | 60 | 48 | 42 | 58.7 | 68 | 60 |

**설계 근거**: 도시정비법상 재건축 연한은 준공 후 30년(서울시 기준). 30년 도달 시
안전진단·정비구역 지정 기대가 가격에 선반영되므로 42점 저점 후 반등시킨다.
단, 반등은 `DEVELOPMENT` 축의 정비사업 단계와 중복 계상되지 않도록
**AGE 반등폭을 68점으로 제한**하고 실제 사업 진행은 DEVELOPMENT에서 평가한다.

**근거 예**: `2003년 준공, 23년차 — 리모델링/재건축 논의 시작 구간`

### 5.9 DEVELOPMENT — 호재 (w=7)

**해당 필지·인근 기준**. 확실성 단계별 계수를 곱한다.

| 호재 유형 | 기본 배점 | 반경 조건 |
|---|---|---|
| GTX·신설 지하철역 | 35 | 역사 예정지 1km 이내 |
| 기존 노선 연장·신설 | 25 | 1km 이내 |
| 대규모 정비사업(재건축·재개발) 본인 단지 | 40 | — |
| 인근 정비사업 | 15 | 500m 이내 |
| 대규모 개발지구(신도시·복합개발) | 25 | 3km 이내 |
| 대기업 사옥·산업단지 유치 | 20 | 3km 이내 |
| 대형 공원·수변공간 조성 | 12 | 1km 이내 |
| 도로·교량 신설/확장 | 10 | 1km 이내 |
| 학교 신설 | 10 | 1km 이내 |

**확실성 계수**:
| 단계 | 계수 |
|---|---|
| 착공/확정 고시 | 1.00 |
| 실시계획 인가 | 0.85 |
| 기본계획 수립·예타 통과 | 0.60 |
| 추진 발표·검토 단계 | 0.35 |
| 언론 보도·민원 수준 | 0.15 |

```
DEVELOPMENT = min(100, Σ(배점 × 확실성계수))
호재 없음 → 40점 (중립 기준점, 결측 아님)
```

**악재는 감점**: 혐오시설(소각장·변전소·교도소 등) 확정 → −20/건

**출처 필수**: 각 호재는 `{title, stage, source_url, announced_at}` 을 반드시 갖는다.
MVP는 사용자 입력 + 관리자 큐레이션 DB. 자동 수집은 Phase 5.

### 5.10 INVESTMENT — 투자 기회 (w=8)

**소스**: 국토부 실거래가 시계열 (반경 1km, 최근 36개월)

```
INVESTMENT = 0.35×상승모멘텀 + 0.25×상대저평가 + 0.20×거래유동성 + 0.20×공급희소성
```

**(a) 상승 모멘텀** — 인근 단지 평단가 최근 12개월 변동률 g
```
piecewise(g, [[-0.15,0],[-0.05,25],[0,45],[0.05,65],[0.10,82],[0.20,95],[0.30,100]])
```

**(b) 상대 저평가** — 동일 생활권 상위 단지 평단가 대비 갭
```
gap = 1 − (본단지평단가 / 생활권상위25% 평단가)
piecewise(gap, [[0,40],[0.10,60],[0.20,80],[0.30,95],[0.45,100]])
```
갭이 클수록 따라 오를 여지(키맞추기)가 크다는 가정. 단, 갭 0.45 초과는 **구조적 열위**
가능성이 있어 상한 처리한다.

**(c) 거래 유동성** — 최근 12개월 단지 거래건수 / 총세대수
```
turnover = 거래건수 / 세대수
piecewise(turnover, [[0.005,10],[0.015,45],[0.03,75],[0.05,95],[0.08,100]])
```

**(d) 공급 희소성** — 반경 2km 내 향후 3년 입주 예정 물량 / 기존 세대수
```
supply = 예정물량 / 기존세대수
piecewise(supply, [[0,100],[0.05,85],[0.10,65],[0.20,35],[0.35,10],[0.50,0]])
```
(MVP: 데이터 미확보 시 이 항목 결측 처리 후 (a)(b)(c) 재정규화)

### 5.11 RISK — 커뮤니티 확인 문제점 (감점, 최대 −15)

가산 축이 아니라 **총점 차감**. 근거 없는 감점을 막기 위해 각 항목은
`출처 유형(사용자 직접확인 / 커뮤니티 다수 언급 / 공개데이터)` 을 표기한다.

| 리스크 | 감점 | 판정 방식 |
|---|---|---|
| 층간소음 심각 (벽식구조 + 다수 민원) | −4 | 사용자입력 + 구조 형식 |
| 도로·철도 소음 (간선도로 50m·철도 100m 이내) | −3 | 좌표 기반 자동 |
| 항공기 소음권 | −3 | 소음대책지역 좌표 대조 |
| 단지 진입 급경사 (평균 경사 8% 이상) | −3 | 고도차/거리 (표고 데이터) |
| 인근 유흥상권 (반경 300m 내 유흥주점 밀집) | −3 | 카카오 로컬 카테고리 밀도 |
| 혐오·기피시설 인접 | −4 | POI 대조 |
| 주차 부족 (세대당 1.0대 미만) | −3 | 공동주택정보 |
| 일조·조망 침해 (전면 고층 차폐) | −2 | 사용자입력 |
| 커뮤니티 다수 지적 기타 | −2 | 사용자입력 |

```
RiskPenalty = min(15, Σ 해당 감점)
```

**표기 원칙**: 감점 항목은 상세 화면에 반드시 사유와 함께 노출한다.
자동 판정 항목은 `[자동판정]`, 사용자 입력 항목은 `[사용자확인]` 라벨을 붙인다.

## 8. 검증 계획

1. **단위 테스트** — 각 정규화 함수의 경계값 (임계 직전/직후/초과)
2. **골든 케이스** — 서울 주요 단지 10곳의 실제 값을 고정 픽스처로 두고 회귀 테스트
   (예: 강남 도곡렉슬 84㎡ / 노원 상계주공 59㎡ / 성남 판교푸르지오 84㎡)
3. **합리성 검증** — 명백히 우수한 단지가 명백히 열위 단지보다 높은 점수인지 순서 검사
4. **결측 내성** — 축 3개를 강제 결측시켜도 총점이 0~100 범위이고 confidence가 낮게 표기되는지
