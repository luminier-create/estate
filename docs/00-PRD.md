# 00. 제품 요구사항 정의서 (PRD)

프로젝트명: **HomeFit** — 아파트 입지 적합도 스코어링 서비스
문서 버전: v1.0 / 작성일: 2026-09-09

---

## 1. 문제 정의

부동산 앱(호갱노노·네이버부동산·아실 등)은 **매물 탐색**에 최적화되어 있으나,
"이 아파트가 **나에게** 좋은가"를 판정하지 못한다.

- 시세·평면·거래이력은 제공되나 **개인의 통근지·생활반경**이 반영되지 않음
- 학군·교통·호재 정보가 분산되어 있어 **단지 간 비교가 정성적**으로만 가능
- 사용자는 결국 엑셀에 수기로 후보 단지를 정리하고 감으로 순위를 매김

## 2. 해결 방식

사용자가 **본인 조건(예산·사무실·자주 가는 장소)** 을 1회 등록하고,
관심 아파트를 **수동 입력**하면, 11개 축의 정량 지표를 수집·정규화하여
**0~100점 적합도 점수와 후보 간 순위**를 산출한다.

핵심 차별점: *매물 검색 서비스가 아니라 **의사결정 보조 서비스***.

## 3. 타깃 사용자

| 세그먼트 | 상황 | 핵심 니즈 |
|---|---|---|
| 실거주 매수자 (1차) | 3~5개 후보 단지를 놓고 고민 | 통근·학군 기준 객관적 순위 |
| 신혼·1인 가구 | 직주근접 최우선, 예산 제약 | 통근 30분 이내 + 가격 합리성 |
| 학령기 자녀 가구 | 학군·안전 통학로 중시 | 초·중·고 도보 접근성 |
| 투자 목적 | 시세 대비 저평가 + 호재 | VALUE·INVESTMENT·DEVELOPMENT 축 |

## 4. 범위 (Scope)

### 4.1 MVP 포함 (Phase 1~3)

- 구글 계정 로그인/회원가입 (Firebase Auth, Google OAuth 단일 제공자)
- 내 정보 설정: 목표 매입 금액, 사무실 위치, 자주 가는 장소(N개), 가구 구성
- 아파트 수동 등록: 단지명(주소 자동완성), 전용면적(평/㎡ 상호변환), 매입 희망 금액
- 11개 축 자동 분석 및 0~100 점수 산출
- 후보 단지 순위표 + 축별 레이더 차트 + 상세 근거 뷰
- 보류함 — 후보에서 빼되 기록은 남김 (삭제는 되돌릴 수 없어 고민 중인 단지에는 과함)
- 가중치 프리셋 4종 + 사용자 커스텀 가중치
- 반응형 (모바일 우선) + PWA 설치

### 4.2 MVP 제외 (후속)

- 매물 자동 크롤링·연동 (법적 리스크 + 서비스 정체성 밖)
- 실시간 알림/가격 변동 푸시
- 다중 사용자 공유·협업 (배우자 공동 검토)
- 전세/월세, 오피스텔·빌라 (Phase 5 확장)

### 4.3 명시적 비목표

- 부동산 중개·거래 알선 (공인중개사법 저촉)
- 투자 수익 보장·매수 권유 (자문업 규제 회피 → 전 화면 면책 고지)

## 5. 사용자 스토리

```
US-01  사용자로서 구글 계정으로 3초 안에 로그인하여 기기 간 데이터를 공유하고 싶다.
US-02  사용자로서 사무실 주소를 지도에서 찍어 등록하고, 통근 기준 시간을 정하고 싶다.
US-03  사용자로서 자주 가는 장소(강남역 등)를 여러 개 등록하고 중요도를 주고 싶다.
US-04  사용자로서 부동산 앱에서 본 아파트를 단지명·면적·금액만으로 빠르게 등록하고 싶다.
US-05  사용자로서 등록한 아파트가 내 조건에 몇 점인지, 왜 그 점수인지 근거를 보고 싶다.
US-06  사용자로서 후보 단지들을 한 화면에서 순위·표로 비교하고 싶다.
US-07  사용자로서 "학군이 더 중요하다"처럼 가중치를 조절해 순위 변화를 보고 싶다.
US-08  사용자로서 이 단지에 어떤 호재/리스크가 있는지 출처와 함께 확인하고 싶다.
US-09  사용자로서 지하철로 사무실까지 환승 없이 가는지 알고 싶다.
US-10  사용자로서 모바일에서 이동 중에도 동일한 기능을 쓰고 싶다.
```

## 6. 핵심 화면 (7종)

| # | 화면 | 경로 | 설명 |
|---|---|---|---|
| 1 | 랜딩/로그인 | `/` | 서비스 소개 + 구글 로그인 |
| 2 | 온보딩 | `/onboarding` | 3스텝: 예산 → 사무실 → 자주 가는 장소 |
| 3 | 대시보드 | `/dashboard` | 후보 단지 순위 카드 리스트 |
| 4 | 단지 등록 | `/properties/new` | 주소 검색 → 면적/금액 입력 |
| 5 | 단지 상세 | `/properties/[id]` | 총점·레이더·11축 근거·지도 |
| 6 | 비교 | `/compare` | 다중 단지 축별 비교표 + 가중치 슬라이더 |
| 7 | 내 정보 | `/settings` | 프로필·가중치 프리셋·계정 |

## 7. 비기능 요구사항

| 항목 | 기준 |
|---|---|
| 성능 | 최초 분석 ≤ 8초, 캐시 히트 시 ≤ 1초, LCP ≤ 2.5s |
| 반응형 | 360px(모바일) ~ 1920px(데스크톱) 무결. 브레이크포인트 sm/md/lg/xl |
| 접근성 | WCAG 2.1 AA. 색상 외 정보 전달 수단 병행(점수 라벨) |
| 가용성 | 외부 API 장애 시 해당 축만 `데이터없음` 처리 후 가중치 재정규화 |
| 비용 | 무료 티어 내 운영. API 호출 캐싱으로 단지당 최초 1회만 외부 호출 |
| 보안 | Firestore 규칙으로 사용자 본인 문서만 R/W. API 키는 서버 전용 |
| 법적 | 전 분석 화면 하단 면책 고지. 데이터 출처·기준일 명시 |

## 8. 성공 지표 (제품 관점)

- 온보딩 완료율 ≥ 70%
- 사용자당 등록 단지 수 ≥ 3 (비교가 성립하는 최소치)
- 분석 실패율(축 3개 이상 결측) ≤ 5%

## 9. 리스크 및 대응

| 리스크 | 영향 | 대응 |
|---|---|---|
| 외부 API 무료 쿼터 초과 | 분석 불가 | 단지 단위 캐시(TTL 30일) + 일일 호출 상한 + 큐잉 |
| 커뮤니티 문제점(층간소음 등) 데이터 부재 | RISK 축 공백 | 사용자 자가입력 + 체크리스트 설문 방식 병행 |
| 호재 정보의 정성적 성격 | 점수 신뢰도 | 확정/추진/검토 3단계 라벨 + 출처 링크 필수 |
| 실거래가 API 지연(신고 30일) | 시세 왜곡 | 최근 6개월 윈도우 + 기준일 표기 |
| 크롤링 법적 리스크 | 서비스 중단 | 공식 Open API만 사용. 스크래핑 전면 배제 |

## 10. 면책 고지 (전 분석 화면 필수 노출)

> 본 서비스가 제공하는 점수와 순위는 공개된 공공데이터를 기반으로 한 **참고 정보**이며,
> 특정 부동산의 매수·매도를 권유하거나 투자 수익을 보장하지 않습니다.
> 실제 거래 전 반드시 현장 확인 및 전문가 상담을 거치십시오.
> 데이터 출처와 기준일은 각 항목에 표기됩니다.
