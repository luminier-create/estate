# 외부 API 연동 절차

이 앱의 외부 API 는 전부 무료 티어라 호출 수가 제한되고, 언제든 실패할 수 있다.
**키가 없어도 앱 전체가 동작해야 한다**는 원칙을 깨지 않는다.

## 0. 먼저 읽는다

- `docs/03-DATA-SOURCES.md` — 기존 API 스펙과 발급 절차
- `docs/10-KNOWLEDGE.md` — 정책·비용 현황. 무료 한도와 만료 시점을 확인한다

## 1. 인터페이스부터

`src/lib/providers/types.ts` 에 인터페이스를 정의하거나 기존 것을 재사용한다.
**구현보다 인터페이스가 먼저다.** 나중에 Provider 를 교체할 수 있어야 한다.

## 2. Mock 을 먼저 만든다

`src/lib/providers/mock/` 에 결정적(deterministic) 구현을 넣는다.
**랜덤을 쓰지 않는다** — 같은 입력에 같은 출력이어야 골든 테스트가 성립한다.
거리·해시 기반으로 그럴듯한 값을 만든다.

## 3. 실구현

`src/lib/providers/<이름>/index.ts`. 흔한 함정:

- **응답 형식** — XML 인지 JSON 인지. 국토부는 XML 이다
- **파라미터 순서** — 카카오는 `x=경도, y=위도` 다
- **인증키 인코딩** — 이중 인코딩이 대표적 실패 원인
- **제외해야 할 데이터** — 국토부 실거래는 계약 해제 건(`cdealType === 'O'`)이 섞여 온다
- **타임아웃** — 개별 6초. 전체 파이프라인을 막지 않게 한다

## 4. 전환을 자동으로

`src/lib/providers/index.ts` 에서 환경변수 유무로 real/mock 을 고른다.
`.env.example` 에 키를 추가하고 **주석으로 발급 경로를 적는다**.

## 5. 캐시와 쿼터 (빠뜨리지 않는다)

`src/lib/cache-keys.ts` 에 키 생성과 TTL 정책을 추가한다.

- 좌표는 소수 4자리로 뭉친다 (약 11m — 인접 좌표가 같은 캐시를 쓰게)
- 변하지 않는 데이터는 TTL `null` (무기한)
- **호출을 `cachedCall` 로 감싼다.** 캐시 적중 시 쿼터를 소모하지 않아야 한다
- `DEFAULT_QUOTA` 에 일일 상한을 보수적으로 잡는다. 무료 티어 한도보다 낮게

## 6. 결측 내성 확인

`src/lib/analyze.ts` 에서 `safe()` 로 감싸 실패가 해당 축만 결측으로 만들게 한다.
**API 하나가 죽어도 나머지 축으로 점수가 나와야 한다.**

## 7. 테스트

```bash
npm test
```

- 캐시 키 분리 (다른 입력이 같은 키가 되지 않는가)
- TTL 만료·무기한
- 쿼터 차감과 상한 도달 시 차단
- 캐시 적중 시 쿼터 미소모
